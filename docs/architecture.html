Factory Inventory Management System

Architecture overview — a full-stack demo application with a Vue 3 frontend, a Python FastAPI backend, and in-memory mock data (no database). Built for demonstrating inventory, order, demand, backlog, and spending workflows.

Vue 3 SPA

  • Vue Router (6 views)

Server

FastAPI Application

Port 8001 · Uvicorn
  • REST endpoints under /api
  • Pydantic request/response models
  • Query-param filtering & aggregation
  • CORS enabled for local dev

Data

In-Memory JSON Store

server/data/*.json
  • Loaded once at startup
  • No persistence between restarts
  • 7 datasets (inventory, orders, etc.)
No database is used. All data is generated/stored as static JSON files and loaded into memory by server/mock_data.py on server start.

Data Flow

1

User interacts with filters

Time Period, Warehouse, Category, and Order Status filters are set in FilterBar.vue and held in the useFilters composable as shared reactive state.

2

View triggers a data load

A view (e.g. Dashboard.vue, Inventory.vue) watches the filters and calls a method in client/src/api.js, passing the current filter values as query params.

3

Axios calls the FastAPI backend

A GET request is sent to http://localhost:8001/api/... with query parameters such as warehouse, category, status, and month.

4

Server filters in-memory data

main.py applies apply_filters() / filter_by_month() against the datasets loaded by mock_data.py, then validates the response shape with Pydantic models.

5

JSON response returns to the client

The filtered, validated JSON is sent back over the CORS-enabled connection and stored in a raw ref (e.g. allOrders, inventoryItems) in the view.

6

Computed properties render the UI

Vue computed properties derive totals, charts, and tables from the raw refs, so the UI updates reactively whenever filters or underlying data change.
